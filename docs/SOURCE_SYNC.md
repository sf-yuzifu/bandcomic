# 漫画源多选与逐源 Cookie 同步（P1-44）

AstroBox V4 同步器在「漫画源配置」页一次读取 `/config`，显示完整源目录，再将所选源及对应 Cookie 操作发送到腕上漫画。配套快应用最低 `versionCode` 仍为 **318**，继续使用已有 Interconnect 消息，不要求原生 fetch。

## 使用流程

1. 输入漫画源配置入口的 API 基础地址，例如 `https://api.example.com`、`http://127.0.0.1:8080/api`。裸地址默认 HTTPS；明确输入的 HTTP 会保留。支持 localhost、IP、端口和路径前缀。
2. 输入完成后点击「读取 / 刷新配置」，读取一次 `<基础地址>/config`。逐字输入、粘贴、删除及普通失焦不会发请求，也不会逐字重建输入框；同步复用已经读取的目录，再次点击读取按钮才重新获取。
3. 查看每个源的 **名称、key 和 API 地址**。首次单源配置默认选中，首次多源配置需要明确勾选；无效条目显示具体字段原因且不能勾选。每页最多 8 条，可全选有效源或清除选择。
4. 为每个源分别选择 Cookie 操作。可以为未勾选的源整理草稿，但不会发送该项。
5. 点击「同步所选源到设备」。插件先验证完整载荷，再固定配置快照和目标设备，完成启动/握手后发送；状态卡片持续显示原配置入口、捕获设备及配置/Cookie 的命令发送结果。

配置入口只用于获取目录，各源实际请求地址取其 `apiUrl`。名称可以相同，key 是设备配置与 Cookie 的身份；同 key 下发具有更新覆盖语义，不创建另一份独立源。

## Cookie 操作

| 操作 | 行为 |
| --- | --- |
| 保留 Cookie | 默认操作，不发送该 key，保留设备已有值 |
| 更新 Cookie | 编辑该源的输入框，发送新字符串；空白更新被拒绝 |
| 清空 Cookie | 明确发送该 key 对应的空字符串；设备后续请求不附加该源的 Cookie 头 |

输入框按密码字段显示，连续输入只更新内存草稿，点击同步时以最新内容校验并生成载荷。更新内容最多 16KiB（UTF-8 字节），不接受换行或控制字符；空白/非法更新在任何启动及发送前拦截，明确清空使用清空按钮。不同源的输入和操作独立，只发送最终勾选的 key。

Cookie/选择草稿只保存在本次插件运行内，按 **规范化配置入口 + 源 key + API 地址** 隔离；同一身份刷新可恢复草稿，另一入口或同 key 的 API 地址变化不自动继承。草稿有界，插件重启后重新读取并填写；持久化沿用后续 P3-26。

## 配置校验

`/config` 返回非空的 `key → 配置对象`，响应最多 256KiB、最多 128 个源。单条无效配置不阻止其他有效源被选择；所有条目无效时没有可发送计划。

| 字段 | 要求 |
| --- | --- |
| key | 非空、≤512 字节，无首尾空白、控制字符及路径分隔符；排除 `using/type/__proto__/constructor/prototype` 等设备或消息保留键 |
| `name` | 非空字符串，≤4096 字节 |
| `apiUrl` | 完整 HTTP(S) 基础 URL，≤8192 字节；规范化主机/默认端口并去掉末尾斜杠；不使用 URL 用户信息、查询串、片段或占位符 |
| `detailPath` | 以单个 `/` 开头，包含 `<id>` |
| `photoPath` | 包含 `<id>`；`<chapter>` 可选，兼容单篇接口 |
| `searchPath` | 包含 `<text>` 和 `<page>`，支持将占位符放在查询参数里 |
| `type` | 可选；提供时为非空字符串 |

接口路径不接受完整 URL、空白、反斜杠或片段，长度 ≤8192 字节；占位符必须闭合且属于该接口当前支持的字段。已有扩展字段保留在原配置中，选择过滤不会丢掉它们。

错误分别标为地址、网络、HTTP 状态、JSON 或具体源/字段问题。连接阶段使用 15 秒连接超时；响应与字段预算属于配置校验，不表示取消或替代宿主 HTTP 层的全部超时行为。

## 快照、设备和迟到事件

- 地址改变立即使旧目录在模型中失效，保留宿主正在编辑的输入框；读取、导航等显式操作再刷新界面。读取状态、目录及所有选择/输入事件关联表单代际；发送前始终核对最新草稿，旧读取结果、旧源输入、旧选择按钮和旧同步按钮不能操作新目录。
- 同步之前构造完整、不可变的配置和 Cookie 消息；握手后发送原计划，不再读取可变表单或重新获取 `/config`。
- 等待期间的源选择/Cookie 编辑事件不改变已捕获载荷。配置入口改变会停止原未发送计划；连接切换、断开或与捕获目标不一致时停止剩余发送。
- 设备核对发生在捕获目标、启动/握手及各消息发送前。其他正在进行的设备管理/上传操作完成后才开始此同步，避免覆盖共享握手续体。

## 兼容消息与发送结果

所选源继续作为单键对象数组发送：

```json
{
  "type": "source_config",
  "configs": [
    { "A": { "name": "漫画源 A", "apiUrl": "https://a.example.com", "detailPath": "/album/<id>", "photoPath": "/photo/<id>", "searchPath": "/search/<text>/<page>" } },
    { "B": { "name": "漫画源 B", "apiUrl": "https://b.example.com", "detailPath": "/album/<id>", "photoPath": "/photo/<id>", "searchPath": "/search/<text>/<page>" } }
  ]
}
```

Cookie 修改继续使用平铺的 key → 字符串格式，不新增会被旧端当作 Cookie key 的 session 等字段：

```json
{
  "type": "cookie",
  "A": "session=xxx",
  "B": ""
}
```

保留操作不出现在 Cookie 消息中；没有修改时不发送 Cookie 消息。两个载荷在发送前都完成校验，单个控制消息上限 64KiB，超限提示减少选择，不静默丢源。

插件先发送配置，再发送 Cookie 修改。配置发送异常时不继续发送 Cookie；配置已发送但 Cookie 异常或连接改变时显示部分命令已发送。成功传输显示 **「命令已发送，待设备核实」** 和源/Cookie 修改数量。

当前两类旧协议消息没有设备持久化回报；不能将命令发送完成当作设备已保存，也不承诺两类消息原子提交。可重新读取设备源列表确认配置；Cookie 应通过该源的实际访问结果核实。设备按各 key 合并接收，未选的既有源及保留 Cookie 不因本次同步被清除。
